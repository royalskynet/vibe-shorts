# 寫稿規則（TREATMENT.md 怎麼填）

機械檢查：precheck「寫稿規則」門查表格欄位、空動作、抽象詞清單、衝擊事件類型；「藏字檢查」門查每張卡藏字後還有沒有自己的畫面；`seek_check.mjs` 查震動對時。

敘事結構照 `refs/vkv/narrative-templates.md` 的六段式。本檔只補兩條「畫面怎麼寫」的規則，出處是 claude-motion `direction.md` §1、§4（見 `docs/RESEARCH-claude-motion.md`）。作者標明這些是創作假設，沒有盲測證據。

## 1. 每張卡寫一個能畫的動作

「內容」欄寫字幕，「動作」欄寫畫面上**誰對什麼做了什麼、什麼狀態改變了**。

- 用動詞：蓋章、劃掉、堆疊、壓下、拉開、翻頁、填滿。
- 不寫「科技進步」「意義重大」這類抽象詞。這類詞畫不出來，會退化成換字卡。
- 關鍵機制發生之前，先讓觀眾看到它壞在哪裡。要靠字幕才知道修好了什麼，代表前面沒展示問題。
- 收尾顯示動作留下的狀態，不只出一張總結字卡。

自查：把「內容」欄蓋住只看「動作」欄，還講得出這張卡在說什麼嗎？講不出就重寫動作。

## 2. 一個衝擊事件只有一個時間點

主體接觸、鏡頭震動、音效、餘振都引用同一個事件時間 t0，不各自寫秒數。

- 頁面把事件推進 `window.EV`，`mix.py` 已經照 `events.json` 放音效（`films/flt-11days/mix.py:132`）。
- 鏡頭震動和餘振也要從同一筆事件算，不另寫秒數。改一個時間點時，聲音和畫面才會一起移動。頁面這樣寫並匯出：

  ```js
  // EV 先建好，震動從 EV 取，不另寫秒數
  const SHAKES = window.EV.filter(e => e.type === 'stamp').map(e => e.t);
  window.SHAKES = SHAKES;   // seek_check.mjs 會逐筆比對 EV；沒匯出＝沒查，precheck 判 FAIL（沒有衝擊事件就匯出空陣列）
  ```

  flt-11days 還是舊寫法（`SHAKES = [CARD * 8 + 1.0]`，值和 stamp 事件相同但寫了兩次），因為改頁面就要重渲染，沒改。
- 動作分階段：準備 → 加速 → 接觸（t0）→ 餘振衰減 → 停留。餘振超過衰減時間要歸零，不是無限小抖。
- 輕的動作不加鏡頭震動。整支片不要一直抖。

## 3. 旁白稿 narration.md

每支片要有 `films/<片>/narration.md`，用 `## 段名` 分段，內文就是要念的字。**段數 3–8，段名與順序自由**（使用者 2026-11-10 刪掉「鉤子 → 轉折 → 落點」的固定模版，改成量對標帳號的形狀，判準見 `docs/寫稿原則.md`）。提問只寫在說明欄，正片不放（使用者 11-03 定）。

precheck 兩道門（判準寫在 `scripts/precheck.py` 開頭的常數，片子這邊改不到）：

- **旁白稿結構**：三段齊、順序對、不空，落點後面沒有別段，沒有「## 提問」段。鉤子第一句 ≤25 字，要有「你」或是問句。
- **旁白進成片**：先跑 `.venv/bin/python scripts/narration_check.py films/<片>`，它用 Whisper 聽成片本身，存 `out/narration-report.json`。門判三件事：聽寫跟稿的相似度 ≥0.85（沒混進去或吃字會掉下來）、第一個字在 0.5 秒內。報告用 sha256 綁成片和稿，任一改過要重跑。

純音樂的片會被判失敗。Whisper 在純音樂段可能幻聽出「优优独播剧场」這類句子（費馬片實測），相似度一樣過不了。

```
## 鉤子
滑 IG 的時候，你是不是總覺得大家都過得比你好？
## 機制
人緣好的人出現在很多人的名單上，被重複算了很多次。
## 轉折
同一件事，也發生在你等公車的時候。
## 落點
你看到的別人，是被人多的地方挑過的樣本。
```

## 4. 定稿前必過反方稽核（2026-10-14 加，必跑不可省）

旁白稿和 `SOURCES.md` 寫完、配音之前，跑 `/research` 第三輪 devil's advocate 挑戰稿裡的每個事實與推論，避免 AI 幻覺的數字或推論被發出去。

1. `scripts/devils.sh films/<片>`：把稿＋來源合成 `audit/claims.md`，交給 research skill 的 `devils_advocate.sh`（codex → opencode，獨立上下文、上網找反證、每條要 URL＋摘錄），證據包寫到 `audit/devils-advocate.md`。exit 3 時主 session 照 research 的 `round3-devils-advocate.md`「派遣 prompt 模板」派一次 subagent，報告填 `audit/claims.md`。只給三個路徑，不附自己的看法。
2. 主 session 對正反雙方套協定的七道證據閘門，逐爭點裁決，寫 `audit/verdicts.md`：

```
engine=<codex|opencode|subagent>
narration_sha: <narration.md 的 sha256>
sources_sha: <SOURCES.md 的 sha256>

## 爭點 1
VERDICT: PRO_WINS | CON_WINS | SPLIT | UNRESOLVED
REASON: <過了或沒過哪道閘門，一句>
```

3. `CON_WINS`／`SPLIT` 改稿（推翻就刪或改，部分成立就把範圍寫進那句事實的主詞或數字：年份、地點、對象、「曾經」），反證來源補進 `SOURCES.md`；`UNRESOLVED` 刪掉該句或換成有證據的事實，不寫成定論。改完重跑 1–2，sha 要對上最後的稿。
   - **禁止防衛性中立句**（2026-10-14 使用者定，嚴重度同 CLAUDE.md）：不准為了過稽核加「兩份調查問法不同」「不能直接比較」「不代表全部」「不能說成同一個原因」這類不帶資訊的聲明句。限定要長在事實裡，不另起一句替自己辯護。
   - 稿子不替任何論點背書：只呈現數據傾向，結論留給聽眾；落點重述數據，不給建議。

precheck「反方稽核」門判：證據包每個爭點有 URL＋摘錄或標 `NO_EVIDENCE_BACKED_OBJECTION`、每個爭點都有 VERDICT＋REASON、sha 對得上現在的稿與來源。稽核後改一個字就要重跑。

## 5. 對談片（女主＋Claude）寫法（2026-10-16 使用者核准）

證據在 `docs/RESEARCH-dialogue.md`：IG 三個英文帳號 46 支逐字稿。中文沒有同格式的片，照英文爆款的寫法，台詞用台灣中文寫，不逐句翻譯英文原稿。

2026-10-18 使用者定：別人的台詞不能照抄（直譯版 sixty-one 因此不發）。原稿只借結構，台詞重寫；precheck「台詞非照抄」門把每句和 `refs/dialogue-corpus/originals-zh.md` 的直譯句比，相似度 >0.6 就擋；第 1 條的圈內梗不算。

1. 每支至少 2 個中文圈內梗：「你說得完全正確」、開新對話、Claude.md、Codex 比較、被降智、context 滿了、額度用完。
2. Claude 冷面、照字面講，負責拆穿女主；女主是愛面子、偷懶的人類。每 2–4 句一個笑點。
3. 收尾用回扣或女主吃虧，不收溫情。問觀眾的話放說明欄。正片不放提問段。
4. 每句 4–10 字，一句一個意思。女主台詞要有台灣語氣詞（欸、蛤、喔、啦）。例外兩種，語料量過：鉤子句可到 15 字（46 支鉤子句中位 6 個英文字，其餘句 4 個）；1–3 字的短回嘴可以用（≤2 個英文字的句子占 32%，例：「61 times.」「Done.」）。
5. 「AI 沒有記憶」先不當主梗（三支同題片一高一低，證據弱）。

以下 6–9 條 2026-10-16 加，證據是 YouTube 9 支擬人 AI 短劇（48 萬–3952 萬播放，`docs/RESEARCH-dialogue.md` 補充段第 8–11 條）：

6. 每個笑點都是上一句的直接回答。答案照字面講，反過來打到發問的人。不回答上一句的台詞就是邏輯斷點。
7. 「你說得完全正確」只放在女主自貶之後，同意就是補刀。不放在開頭當奉承。
8. 三段加碼：同一個問題或證據連給三次，一次比一次重，第三次最荒謬。
9. 收尾回扣第一句：片頭問過的話，片尾換個情境再出現一次，意思翻過來。
10. 每個因果要在稿裡交代（例：登入為什麼壞了→「我用猜的」「猜錯了」）。觀眾補不起來的因果算斷點。

## 7. 單人旁白科普稿（2026-10-29 使用者定，新片預設）

口吻與畫面對標 IG @boundless__explorer（無邊探索，1,062 粉、11 支，11-03 全數轉寫實測，`refs/boundless/ANALYSIS.md`）與我們的 france／scam-map。10-29 版引的「塞車 127 萬、沒水 104 萬、胖瘦 86 萬」不是這個帳號，已刪；這個帳號最高 8,681 讚，選題的爆款證據另照 viral-scout。

1. 單人 m3 男聲旁白，不寫對話、不分角色。
2. 旁白 300–420 字（無邊探索 303–422 字），片長 60–85 秒。語速照無邊探索中位 5.2 字／秒（它的量法是字數 ÷ 片長，含停頓）：`pace.json` 設 `{"tempo": 1.15, "gap_line": 0.45, "gap_section": 0.8}`（使用者 11-04 定，取代 11-03 的 1.3）。加速與縮停頓是同一個目標，不要兩個都加碼：taipei-silence 用 tempo 1.3 加 0.3／0.6 停頓，扣掉片尾卡後是 5.88 字／秒，比無邊探索最快的 5.53 還快，聽起來很趕。量自己的片要扣掉片尾靜止卡。
3. 開場 10 秒內三件事：觀眾自己的感受或成見（「你會不會覺得…」）→ 一句翻轉（「但事實可能跟我們想的不太一樣」）→ 知道答案有什麼用。不先鋪背景。
4. 一支只講 1 個核心機制，拆 2–3 步；不列清單、不塞多論點。
5. 每一步至少 1 個可查來源的數字或具體比喻；來源寫 SOURCES.md，不唸進旁白。
6. 口吻細則見 `docs/寫稿原則.md`。一句講完一個因果，每句 ≤35 字，用「而且／可是／所以／只是」接起來；不要把一個意思剁成三句短句（使用者 2026-11-01 定，取代原「每句平均 ≤12 字」：剁碎的短句「根本不是人類說話」，無邊探索口播實測每句 20–35 字）。念的時候在逗號換卡，每個短語 8–16 字；每句對應畫面一個大字關鍵詞。
7. 不寫懶人包段（使用者 10-30 定：整支片就是懶人包，結尾再總結一次是重複）。
8. 結論收在落點，正片不放提問、不加收尾段；問觀眾的話寫在說明欄。落點立場是請大家多關心這件跟生活有關的公共事，一起讓台灣更好；不寫「應該」「都能」這類把結論當理所當然的句子（使用者 10-30 定）。不口頭求追蹤，追蹤引導放說明欄。
9. narration.md 段數 3–8、段名與順序自由（2026-11-10 起，不再用「鉤子／機制／轉折／落點」模版；形狀判準見 `docs/寫稿原則.md`）；§3 的表格格式、§4 反方稽核、§6 禁止清單照舊適用。
10. 寫完必過 humanize（使用者 10-29 定）：照 genie-humanizer 逐句念一遍，改成台灣人口語，例如「輸得越準」改成「越確定會輸」、比例與人數不混講。改完寫 `audit/humanize.md`，首行是 `narration_sha: <sha256>`，下面列「原句 → 新句」；precheck 的「口語化」門核對戳記，改稿後要重過。戳記只核 sha，不看句型；二元對比句（不是X是Y、是X不是Y、並非、與其說…不如說、看似…實則、你以為…其實）另由「無二元對比句」門逐行擋（11-13 定），直接講 Y。

## 8. 爆點結構（2026-11-06 加；使用者退 dunning-kruger：「稿子太無聊，後面沒有爆點」）

借鏡 Melvynx/video-agent-skills `studio-script/references/script-rules.md`（MIT）。§7 照舊，這節補「留人」與「收尾」。

1. **鉤子打分**：第一句 ≤15 字，帶數字、專有名詞或反常識說法之一。五項各 0–2 分：具體／張力／跟觀眾有關／快／真實，總分 ≥7 才留。
   - 打分前先寫 3 個不同類別的鉤子：至少一個停滑類（打破迷思「台北其實不是藍大於綠」、具體數據「藍綠只差六百四十一票」、直接提問），一個留人類（故事從中間開場、自白「我自己也這樣想過」、說出觀眾心裡的話）。三個都打分，留分最高的；同分選停滑類（借鏡 rediumvex/viral-hooks-skill MIT 十類鉤子，2026-11-08 補）。
2. **開一個懸念，留到最後才關**：鉤子丟出的問題，前 80% 只給線索不給答案。
3. **中段再鉤一次**：40–60% 處放一個新問題、新數字或翻轉（「但這還不是最危險的」），不准平鋪直敘撐到底。
4. **不准連 3 句純說明**：每 2 句內要有一個具體畫面、數字或觀眾自己的經驗。
5. **爆點放後 20%**：最反直覺的那個事實壓在最後 20%，前面不先洩。
6. **結尾回扣第一句**：落點最後一句呼應或回答鉤子（讓重播接得上），不總結。禁「總之／所以說／以上就是／謝謝收看」。§7 第 8 條的公共關懷立場放在爆點之後一句帶過，不另開段。

## 9. 疑點型寫法——司法與爭議案件（2026-11-24 加；幣想案系列調研沉澱）

題型：一個案件有多少疑點，一支片只拆一個，冷靜理性呈現，反思留給觀眾。證據帳 `refs/VIRAL-LEDGER.md`「幣想案系列：司法疑點寫法對標」。

1. **爆款分層，先認清自己站哪層**：冤案平反（800 萬級，要真人故事線）＞法庭戲劇（百萬級，要畫面衝突時刻）＞概念解說（70 萬級，如 What is hearsay 77 萬）。單人旁白＋插畫格式在第三層；有畫面衝突的支（車輪戰、翻供）才借第二層的寫法。
2. **四種鉤子型，按機制挑**：
   - 數字悖論：兩個可證數字對不上（起訴 1544→判決 485），疑點自己浮出來，最強；
   - 概念解說：案件反常事實當鉤→白話法律概念→回到案件問句（釋字、證據法則、沒收、罪數這類法條機制適用）；
   - 法庭戲劇：程序或庭審裡的荒謬落差（80 傳 52 到、證人兩套說法）；
   - 平反借法：被告自稱被害者這種反常身分反轉當鉤。
3. **一支一個疑點，不下結論**：只呈現「哪裡對不上」，不說「冤／不冤」。評價句（活該、灌水、亂判）都不寫；觀眾自己得出結論才會轉。
4. **主張分層標示**：檢方說／法院認定／辯方說三層分開，辯方說法一律帶「辯方說」，不可證的不進旁白事實（同 §7 第 5 條來源規則）。
